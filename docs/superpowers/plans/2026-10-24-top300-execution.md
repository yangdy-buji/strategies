# TOP300源码改进实施计划

> 用户已确认按审查建议执行。使用 subagent-driven-development 在隔离工作树并行处理互不重叠的三组策略，原始策略、历史排名与旧修复候选保持可追溯。此次不下单、不部署；先前推送豁免仅针对先前推送。

**目标：** 对全部300项给出执行状态；实现有明确根因的修复，以及边界明确、明确标注取舍的设计候选；为尚需原生执行或数据的项目提供具体验证计划，不把测试通过当成收益提升。

**架构：** 原版Pine或旧候选作为指纹绑定的基线。三组 `analysis/top300/execution/batch_N.json` 记录逐项处理与精确替换补丁。统一加载器检查覆盖、源文件、基线哈希、补丁唯一性与独立复核，生成带中文备注的独立脚本、差异、300卡片、清单和ZIP。绝不覆盖原始源码，不覆盖旧收益。

**技术：** Python标准库、Pine原版本、unittest局部行为验证、静态HTML与JSON/CSV。

## 数据契约

每组100条，范围按原TOP300排名1–100、101–200、201–300。记录格式：

```json
{
  "rank": 1, "sid": 2351, "source_sha256": "原MD哈希",
  "base_kind": "original", "base_sha256": "基线Pine字节哈希",
  "action": "unchanged", "change_type": "none",
  "summary": "个性化本轮处置",
  "patches": [], "resolved": [],
  "remaining": ["未解决的风险及必要设计取舍"],
  "validation_plan": ["可执行的逐笔/样本外验证步骤"]
}
```

- `base_kind`为`original`或`prior_candidate`；有旧候选可沿用，但1776等已有不完整修复必须补齐或暂缓，不能静默声称已解决。
- `action`为`new_patch`、`carry_existing`、`unchanged`、`deferred_design`。
- `change_type`为`correctness`、`design_experiment`、`mixed`、`none`。
- 补丁每条为`{old,new,reason,preserved,validation_cases}`，old须在顺序应用后的代码唯一匹配；new允许空字符串。reason/preserved必须中文说明，不注入源码外部执行。
- `new_patch`须有补丁；其他动作补丁为空。`carry_existing`必须以旧候选为基线；`unchanged/deferred_design`使用原版。
- 所有`new_patch`须独立复核，复核摘要绑定完整记录哈希；拒绝、过期、缺失的复核不能输出可用候选。
- 设计建议若无法确定唯一实现或未经行情验证，不猜测最优参数，记录明确暂缓原因和验收路径。
